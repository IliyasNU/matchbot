# Проверка Matchbot — 3 ноября 2026

Проверены обработчики регистрации и поиска, подбор анкет, схема и миграции SQLite, реакции и уведомления, параллельная обработка обновлений, переводы, скрипты обслуживания, запуск, Docker-конфигурация и тесты. Исходная версия — `eb8b91d`.

## Исправления

| Сценарий | Найденное поведение | Исправление |
| --- | --- | --- |
| Блокировка, удаление или бан во время отправки фотографии в `/matches` | После фотографии отправлялся контакт из ранее прочитанной анкеты | Состояние пары, обеих анкет и блокировок проверяется перед карточкой и повторно перед контактом |
| Смена username во время отправки фотографии | Ссылка могла вести на прежний username | Контакт строится по текущей записи пользователя |
| Отмена уведомлений и повторное создание пары во время отправки другой записи | Отменённые строки оставались в прочитанном списке и могли отправиться вместе с новой очередью | Перед каждым уведомлением повторно читается конкретная ожидающая строка по ID; проверяются статус и срок отправки |
| Перенос отправки на более позднее время после чтения списка | Прочитанный список мог устареть | Отложенная запись пропускается и сохраняется для повторной попытки |
| Очень большие числа, `²` или лишние поля в callback | Возможны `OverflowError` при запросе SQLite и `ValueError` при преобразовании числа | Единый ограниченный разбор ASCII-чисел для ID и страниц, проверка формы callback |
| Слишком большой ID в команде администратора или настройках | Команда могла завершиться ошибкой базы | ID проверяется до обращения к SQLite; команда показывает подсказку при неверном вводе |
| Бан во время подтверждения callback через Telegram | Команда продолжала использовать прежний статус аккаунта и могла установить `active=1` забаненному пользователю | После ожидания Telegram статус аккаунта перечитывается |
| Пустая секретная часть или неверные символы в токене | Некорректная конфигурация проходила первоначальную проверку | Формат проверяется до создания приложения; действительность токена по-прежнему проверяет Telegram |
| Ошибка создания резервной копии или совпадение имён у двух процессов | Мог остаться неполный файл; предварительная проверка имени не исключала одновременную запись | Имя файла резервируется эксклюзивно; соединения закрываются, а неполная копия удаляется при исключении |

Новые регрессионные тесты воспроизвели ошибки доступа, устаревшей очереди и числовых параметров до внесения исправлений. Проверки также сохраняют доступ к существующим парам при обычной паузе анкеты.

## Локальная проверка

Среда: Windows 11, Python 3.12.14, SQLite 3.53.1. Для асинхронных тестов Telegram заменён подставным транспортом. Временные анкеты не создавались в рабочей базе.

- `python -m pytest -q` — **191 тест пройден**, в том числе 59 новых проверок относительно исходной версии.
- `python -m ruff check .` и `python -m ruff format --check .` — пройдены.
- `python -m pip check` — несовместимостей установленных зависимостей не найдено.
- `git diff --check` — пройден.
- `python bot.py --check` — сборка приложения с заведомо подставным токеном и временной базой, без запросов Telegram.
- `docker compose --env-file .env.example config --no-env-resolution --quiet` — проверка Compose без локального `.env`.

Симуляция:

```sh
python scripts/simulate.py --users 1000 --requests 3000 --matches 250 --report data/audit-simulation-1000.json
```

Результат: 1000 временных пользователей, 3000 запросов ленты, 250 взаимных пар и 500 уведомлений. Ошибок контактов, дубликатов уведомлений и нарушений фильтров не обнаружено. Пройдены проверки независимого эталона строгих фильтров, защиты от повторного нажатия, восстановления очереди после перезапуска, удаления и целостности SQLite. Временная база удалена.

Проверка большого пула:

```sh
python scripts/benchmark_scale.py --users 10000 --requests 30 --report data/audit-benchmark-10000.json
```

В каждой из трёх ситуаций выполняются 30 измеряемых запросов: широкий поиск, история 30 лайков, строгие фильтры. Допустимые кандидаты сверяются с независимым эталоном. Это последовательные локальные запросы, а не 10 000 одновременных Telegram-сессий; время зависит от компьютера и текущей нагрузки.

| Ситуация | Подходящих анкет | Среднее время, мс | p95, мс |
| --- | ---: | ---: | ---: |
| Широкий поиск | 9999 | 33.229 | 36.651 |
| История 30 лайков | 9969 | 36.045 | 38.699 |
| Строгие фильтры | 71 | 0.838 | 1.671 |

Все выбранные анкеты соответствовали эталону; целостность SQLite проверена, временные файлы удалены. Таблица описывает этот локальный замер и не является гарантией времени ответа на другом сервере.

## Границы проверки

Доставка через настоящий Telegram и открытие контактов требуют токена и двух реальных аккаунтов; инструкция находится в README. Docker daemon локально не запущен, поэтому выполнена проверка конфигурации, а сборка и запуск контейнера не подтверждены.

Проверка перед отправкой не отменяет запрос, уже переданный Telegram, и не удаляет ранее отправленные сообщения. Уведомления сохраняют семантику доставки «как минимум один раз»: аварийное завершение после принятия сообщения Telegram, но до записи результата в SQLite, может привести к повтору после перезапуска.
