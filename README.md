# Matchbot — знакомства в Telegram

Бот знакомств на Python 3.12+ с русским и английским интерфейсом. Пользователь заполняет анкету, получает рекомендации по совместимости и ставит лайки. Когда симпатия взаимная, оба человека получают уведомление с контактом Telegram.

[Первый запуск на своём компьютере и деплой на VPS](docs/deploy.md). В инструкции есть создание токена, проверка с двумя аккаунтами, запуск через Docker Compose и резервное копирование.

## Что умеет бот

- Регистрация от 18 лет: имя, возраст, пол, предпочтения, город, цель знакомства, до пяти интересов, описание и одно фото.
- Предпросмотр анкеты перед публикацией, редактирование и отмена изменений. Черновик сохраняется между перезапусками.
- Подбор с учётом предпочтений **обоих** людей, общих интересов и цели знакомства; часть показов остаётся случайной.
- Входящие лайки, взаимные симпатии и история контактов с пагинацией.
- Скрытие и возобновление показа анкеты, удаление своих данных с подтверждением.
- Блокировки, жалобы и команды модератора.
- SQLite: анкеты, лайки, пары и очередь уведомлений сохраняются на диске.

## Технологии

- **Python 3.12+ и asyncio** — команды, анкеты, алгоритм подбора и параллельное ожидание ответа Telegram.
- **python-telegram-bot** — Telegram Bot API, кнопки, long polling и фоновые задания для уведомлений.
- **SQLite** — база в одном файле с транзакциями и WAL. Анкеты, пары и очередь сохраняются после перезапуска.
- **python-dotenv** — токен и настройки из файла `.env`.
- **Docker и Docker Compose** — серверный запуск с автоматическим перезапуском и отдельными томами базы и копий.
- **pytest, Ruff и GitHub Actions** — тесты, проверка кода и автоматическая проверка контейнера.

## Запуск на Windows

Установи Python 3.12 или новее, затем открой PowerShell:

```powershell
git clone https://github.com/IliyasNU/matchbot.git
cd matchbot
powershell -ExecutionPolicy Bypass -File .\setup.ps1
```

Скрипт создаст `.venv`, установит зависимости и подготовит `.env`. Если Python отсутствует в PATH, укажи путь: `powershell -ExecutionPolicy Bypass -File .\setup.ps1 -PythonPath 'C:\path\to\python.exe'`.

1. В Telegram открой **@BotFather**, отправь `/newbot` и создай бота.
2. Открой локальный файл `.env` и замени `YOUR_BOT_TOKEN_HERE` на полученный токен.
3. Запусти `start.bat` двойным щелчком или выполни:

   ```powershell
   .\.venv\Scripts\python.exe bot.py
   ```

4. Напиши своему боту `/start`. Переключение языка: `/language`.
5. Отправь `/id`, добавь полученный номер в `ADMIN_IDS` в `.env` и перезапусти бота. Команда `/admin` покажет инструменты модерации.

Для PyCharm выбери интерпретатор `.venv\Scripts\python.exe` и запускай `bot.py`. Пути `.env` и базы определяются относительно проекта, независимо от рабочей папки терминала.

## Запуск на Linux / macOS

```sh
git clone https://github.com/IliyasNU/matchbot.git
cd matchbot
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
```

Заполни `BOT_TOKEN` в `.env`, затем:

```sh
.venv/bin/python bot.py
```

Используй Python 3.12+. Для работы бота процесс должен оставаться запущенным, а компьютер — иметь доступ к Telegram. Ctrl+C останавливает бота.

## Настройки

Токен в репозитории отсутствует. Заполняй его только в локальном `.env`, который исключён из Git.

```dotenv
BOT_TOKEN=YOUR_BOT_TOKEN_HERE
ADMIN_IDS=123456789
DATABASE_PATH=data/bot.sqlite3
SKIP_COOLDOWN_DAYS=7
```

| Переменная | Значение |
| --- | --- |
| `BOT_TOKEN` | Токен от @BotFather, обязателен для запуска |
| `ADMIN_IDS` | Числовые Telegram ID администраторов через запятую; узнать свой: `/id` |
| `DATABASE_PATH` | Путь к SQLite; относительный путь отсчитывается от папки проекта |
| `SKIP_COOLDOWN_DAYS` | Через сколько дней могут вернуться пропущенные анкеты; минимум 1 |
| `MAX_CONCURRENT_UPDATES` | Число одновременно обрабатываемых диалогов: 32 по умолчанию, от 1 до 128 |

## Команды и подбор анкет

| Команда | Действие |
| --- | --- |
| `/start` | Меню, регистрация или продолжение черновика |
| `/browse` | Рекомендованные анкеты |
| `/likes` | Входящие лайки, подходящие под текущие настройки |
| `/matches` | Взаимные симпатии и контакты |
| `/profile`, `/edit` | Просмотр и изменение своей анкеты |
| `/filters` | Возрастной диапазон и поиск по городам |
| `/pause`, `/resume` | Скрыть анкету или возобновить показ |
| `/blocked` | Список заблокированных пользователей и разблокировка |
| `/language` | Русский / English |
| `/cancel` | Отменить черновик |
| `/delete` | Удалить свои данные после подтверждения |
| `/privacy`, `/help`, `/id` | Информация о данных, справка, свой Telegram ID |

Предпочтения по полу, интересы и цель знакомства меняются через `/edit`. По умолчанию поиск охватывает все города и возраст 18–100 лет. Названия городов сравниваются без учёта регистра и лишних пробелов; перевод названий и геокодирование не выполняются.

Чтобы вернуться к черновику, нажми `/start` или снова открой редактирование. После сохранения фильтров или отмены окна удаления бот возвращает открытый черновик. В `/matches` пары открываются по одной, с кнопками навигации. Если человек блокирует бота в Telegram, его анкета скрывается. После разблокировки он может снова показать её командой `/resume`.

### Как устроен подбор

Сначала бот исключает анкеты, нарушающие возрастные, половые и городские фильтры хотя бы одного человека, а также скрытые, забаненные, заблокированные и уже обработанные анкеты. Ранжирование применяется только к оставшимся людям и не может обойти эти ограничения.

Больше шансов получить ранний показ имеют анкеты с общими интересами, той же явной целью знакомства, тем же городом и близким возрастом. Недавняя активность даёт небольшой бонус. Алгоритм также учитывает интересы из последних 30 лайкнутых анкет; этот вклад ограничен и не перевешивает общие явные интересы.

Сначала рассматриваются ещё не показанные или не показанные за последние сутки анкеты; когда таких нет, бот возвращается к наиболее давно показанным. Из соответствующего пула SQLite равномерно выбирает до 256 анкет для ранжирования. Внутри этой выборки в 80% случаев применяется выбор по весам совместимости, в 20% — обычный случайный. Все подходящие анкеты сохраняют шанс попасть в выборку; ограничения по первым ID нет. Повторные вызовы `/browse` не зацикливаются на одной карточке.

Цель и интересы — мягкие факторы: несовпадение цели само по себе не скрывает анкету. Если предпочтение должно быть строгим, используй доступные фильтры `/filters`. Алгоритм не оценивает внешность и не выдаёт вес ранжирования за вероятность взаимной симпатии.

Реализация без внешних API и дополнительных платных сервисов находится в `matching.py`. Базовый вес — 1; бонус за общие интересы — до 5, за одинаковую конкретную цель — 3, за тот же город — 1.5, за близость возраста — до 1, за активность — до 0.5, за интересы из истории лайков — до 1. Это эвристика для первой версии: её качество на реальных пользователях ещё нужно оценить.

При обновлении база версий 1 и 2 автоматически переходит на версию 3 без потери существующих анкет, пар и лайков. Версия 3 добавляет индексы для поиска, истории лайков и связей. Старые анкеты продолжают работать; интересы и цель можно добавить через `/edit`. Перед обновлением рабочей базы сделай резервную копию.

Лента не показывает самого пользователя, незаполненные, скрытые, заблокированные и забаненные анкеты. Лайкнутые анкеты исключаются, пропущенные могут вернуться после заданного срока. Действия работают только на актуальной карточке: старые и чужие кнопки не позволяют поставить лайк произвольному пользователю.

После одностороннего лайка человеку приходит приглашение проверить `/likes`. При взаимном лайке создаётся одна пара, а уведомления получают оба участника. Перед показом контакта бот запрашивает актуальные данные Telegram по числовому ID и использует текущий username. При отсутствии username или ошибке запроса используется ссылка по ID; сохранённый старый username не подставляется. Открытие ссылки может зависеть от настроек приватности Telegram.

Жалоба также блокирует человека. Заблокировать или пожаловаться можно и на существующую пару. Разблокировка не восстанавливает прежние лайки и пары. `/pause` сохраняет уже созданные пары, но скрывает анкету от новых знакомств.

Изменение показанной анкеты, её фильтров, языка или статуса аннулирует лайк и пропуск, но оставляет возможность заблокировать человека или пожаловаться с последней открытой карточки. Новая карточка, действие с прежней карточкой или удаление аккаунта аннулируют её токен. Снимок старого содержимого анкеты в жалобе пока не сохраняется.

## Модерация и данные

Только пользователи из `ADMIN_IDS` имеют доступ к командам:

| Команда | Действие |
| --- | --- |
| `/admin` | Справка по модерации |
| `/stats` | Число анкет, активных профилей, пар и открытых жалоб |
| `/reports` | Первые 20 нерассмотренных жалоб |
| `/inspect USER_ID` | Посмотреть анкету по ID |
| `/ban USER_ID`, `/unban USER_ID` | Заблокировать или разблокировать аккаунт |
| `/resolve REPORT_ID` | Закрыть рассмотренную жалобу |

После снятия бана пользователь должен отправить `/resume`. Жалобы хранятся для ручной проверки; автоматического бана по количеству жалоб нет. Ответы административных команд — на английском.

Бот хранит Telegram ID и username, анкету с выбранными интересами и целью, настройки, время активности, историю показов, отношения между пользователями и Telegram `file_id` фотографии. Сам файл фотографии не скачивается. Интересы и цель показываются в анкете; служебная история показов другим участникам не раскрывается. `/delete` удаляет данные аккаунта и обезличивает жалобы. Для забаненного аккаунта сохраняется минимальная запись о бане, чтобы повторная регистрация не обходила блокировку. Уже отправленные сообщения Telegram и резервные копии оператора этим действием не удаляются.

Возраст указывается пользователем и не подтверждается документами. Перед публичным запуском назначь модератора для проверки жалоб, в том числе на несовершеннолетних пользователей. Доступ к базе и резервным копиям должен оставаться у оператора.

## Проверки

Windows:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m ruff format --check .
.\.venv\Scripts\python.exe bot.py --check
```

Linux / macOS: используй `.venv/bin/python` вместо `.\.venv\Scripts\python.exe`.

`--check` проверяет конфигурацию, создаёт схему базы и собирает приложение **без обращения к Telegram**. Для него нужен токен в допустимом формате; проверка не подтверждает, что Telegram принимает этот токен. Создать базу без токена: `python scripts/init_db.py`.

Автоматические тесты проверяют фильтры, взаимные лайки, конкурирующие транзакции, сохранение данных между перезапусками, повторную отправку уведомлений после временной ошибки, блокировки, жалобы, удаление и права администратора. Полный сценарий регистрации двух людей и взаимного лайка проходит через Telegram SDK с подставным сетевым транспортом. В GitHub Actions предусмотрены Python 3.12 и 3.13 на Ubuntu и Windows.

При показе `/matches` доступ к контакту повторно проверяется после отправки фото: блокировка, удаление или бан во время сетевого ожидания останавливают последующую отправку ссылки. Перед отправкой уведомления бот заново читает его состояние в очереди, чтобы отменённая запись не отправилась после повторного создания пары. Подробности проверки кода: [аудит от 3 ноября 2026](docs/audit-2026-11-03.md).

Проверка семи дополнительных ошибок из внешнего ревью, воспроизводящие тесты и ограничения исправлений описаны в [отчёте от 5 ноября 2026](docs/review-followup-2026-11-05.md).

Реальный запуск с BotFather-токеном и двумя Telegram-аккаунтами ещё нужно проверить:

1. Зарегистрировать две совместимые анкеты на разных языках.
2. Поставить первый лайк и проверить входящее уведомление на втором аккаунте.
3. Ответить через `/likes`; убедиться, что оба человека получили уведомления и открывают контакты.
4. Перезапустить бота и проверить `/matches`.
5. Проверить фильтры, паузу, блокировку, жалобу и удаление анкеты.

### Симуляция с 1000 пользователями

```sh
python scripts/simulate.py --users 1000 --requests 3000 --matches 250 --report data/simulation-report.json
```

Используй Python из `.venv`, как в командах выше. Скрипт создаёт отдельную временную SQLite-базу с вымышленными анкетами и автоматически удаляет её после теста. Рабочая база и `.env` не используются; Telegram заменён записью отправленных уведомлений в памяти.

Проверяются строгие взаимные фильтры по независимому эталону, отсутствие преждевременных повторов, 250 взаимных пар и два уникальных уведомления для каждой пары, очередь после перезапуска, одновременное нажатие одной кнопки, удаление данных и целостность SQLite. Отдельно замеряется время поиска при 999 подходящих кандидатах и при истории из 30 лайков. JSON-отчёт содержит измеренные p50/p95/p99; это время локальной обработки без сетевой задержки Telegram, а не гарантия производительности на другом сервере.

### Проверка на 10 000 и более анкетах

```sh
python scripts/benchmark_scale.py --users 10000 --requests 30 --baseline-ref a050d8832be8d4824d45eec3d9e4a175ab8a7fd6 --report data/benchmark-10000.json
python scripts/benchmark_scale.py --users 25000 --requests 30 --report data/benchmark-25000.json
```

Для сравнения с предыдущей версией требуется локальная история Git с указанным коммитом; обычный `git clone` её содержит. Без `--baseline-ref` измеряется только текущая версия. Используй Python из виртуального окружения. Скрипт создаёт и удаляет отдельные временные базы; `.env` и рабочая база не используются.

В одинаковых условиях проверяются широкий пул, история 30 лайков и строгие фильтры. До и после используются одинаковые исходные данные и время, а допустимые анкеты сверяются с независимым эталоном. JSON содержит p50/p95/p99 и пик Python-выделений памяти для одного дополнительного запроса. Замер памяти исключён из измерений времени и не отражает всю память SQLite/процесса. Это последовательные локальные запросы поиска, а не эмуляция 10 000 одновременных подключений к Telegram.

## Производительность и обработка обновлений

Ранжирование получает максимум 256 компактных наборов признаков; полная анкета с описанием и фото загружается только для выбранного человека. Интересы пользователя и история лайков разбираются один раз на запрос, одинаковые наборы интересов используют общие промежуточные расчёты. Между запросами совместимость не кешируется, поэтому изменения фильтров и блокировки применяются сразу.

Входящие лайки ищутся по индексу получателя. Частичные индексы учитывают город, пол и возраст активных анкет, дополнительные индексы ускоряют работу со связями и удаление данных. При широком поиске `ORDER BY RANDOM()` всё ещё просматривает подходящий пул в SQLite: ограничены передача данных и ранжирование в Python, а не общее число SQL-проверок. Для существенно больших объёмов потребуется повторное измерение и, возможно, другое хранилище/способ выборки.

До 32 диалогов по умолчанию обрабатываются параллельно во время сетевых ожиданий; действия каждого человека выполняются по порядку. Очередь входящих обновлений ограничена 2048 элементами, дополнительно допускается не более 2048 обработчиков, включая выполняемые. При заполнении приём приостанавливается, вместо создания неограниченного числа ожидающих задач. Завершение приложения дожидается уже принятых обработчиков. SQLite остаётся в одном процессе и используется в одном потоке; надёжность транзакций и синхронизация WAL не ослабляются ради скорости. Лимиты отправки сообщений Telegram продолжают действовать независимо от размера базы.

Ответ на лайк не ждёт рассылки уведомлений другим людям: сначала бот показывает следующую карточку, затем будит фоновую отправку. Одновременные запросы запуска объединяются; периодическое задание раз в 5 секунд подбирает оставшуюся очередь и восстанавливает отправку после перезапуска. Ограничитель входящих действий использует монотонные часы в памяти процесса, ограничен 32 768 записями и не пишет SQLite на каждый запрос. После перезапуска его кратковременное состояние сбрасывается.

## Хранение и резервные копии

SQLite использует внешние ключи и WAL. Создание пары и постановка обоих уведомлений в очередь выполняются одной транзакцией. После временных сетевых ошибок отправка повторяется с увеличивающейся задержкой. Перезапуск процесса не стирает очередь.

Доставка уведомлений — «как минимум один раз»: если процесс завершится после принятия сообщения Telegram, но до записи успеха в SQLite, возможен повтор. Постоянные ошибки Telegram фиксируются в журнале и не повторяются бесконечно.

Запускай один polling-процесс на один токен. Файловая блокировка защищает от второго процесса с той же базой; она не координирует независимые базы. Увеличение `MAX_CONCURRENT_UPDATES` помогает перекрывать сетевые ожидания, но не превращает SQLite в хранилище с несколькими параллельными писателями.

Для согласованной резервной копии работающей базы:

```sh
python scripts/backup.py
```

Скрипт использует SQLite backup API и сохраняет файл в `backups/`. Существующий файл не перезаписывается, даже если два процесса одновременно выбрали одно имя. При ошибке копирования созданный неполный файл удаляется. Если изменён `DATABASE_PATH`, передай `--source`; для другого нового файла — `--output`. Для восстановления останови бота, сохрани текущую базу вместе с файлами `-wal` и `-shm` отдельно и восстанови выбранную копию по пути `DATABASE_PATH` без старых файлов WAL/SHM рядом. Задай собственный срок хранения резервных копий.

## Docker

При установленном Docker и Compose заполни `.env` и выполни:

```sh
docker compose up -d --build
docker compose logs -f
```

Оставь `DATABASE_PATH=data/bot.sqlite3`. Том `bot-data` хранит базу, том `bot-backups` — резервные копии. Для каждого токена запускай один экземпляр бота. GitHub Actions собирает образ и проверяет открытие базы и создание копии в контейнере. Команды для первого запуска, обновления и выгрузки копии есть в [инструкции по деплою](docs/deploy.md).

## English quickstart

Python 3.12+ is required. Clone this repository, run `setup.ps1` on Windows, or create a virtual environment and install `requirements.txt` on Linux/macOS. Copy `.env.example` to `.env` if needed and set `BOT_TOKEN` using @BotFather. Run `python bot.py` with the virtual environment's interpreter and send `/start` in the bot's private chat. `/language` switches English/Russian. Run `/id`, add your numeric ID to `ADMIN_IDS`, and restart to enable moderation.

The bot supports adult profiles, compatibility-based discovery using explicit interests, goals and both members' filters, likes, mutual-match notifications, blocking/reporting, and persistent SQLite storage. Discovery mixes weighted recommendations (80%) with random exploration (20%) and avoids recently shown profiles while alternatives remain. Existing profiles keep working after the automatic database migration; add interests and a goal through `/edit`. Automated tests use a fake Telegram transport; live delivery still needs a real token and a two-account check. Full command descriptions, operational limits and backups are documented above.
